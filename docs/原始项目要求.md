# 原始项目要求

以下内容逐字保留用户给出的 motivation、challenge、方案和工作目标，不作修改

**初步执行方案：**

**motivation：**

现有的成熟度诊断方案往往只依赖于白盒分析（源代码级别分析）或黑盒分析（架构层面分析），评估视角单一，缺少全面完善的自动化成熟度诊断工具

**challenge：**

1. 如何结合源代码以及架构级别的分析，并生成一个全面的成熟度评估结果
2. 如何自动化、快速地给出修改意见、解决问题

**方案：**

1. 源代码级别分析阅读相关文档以及源代码内容，获取到服务依赖关系、接口文档、功能架构等内容；架构级别分析通过调用实际云端部署情况，获取到如参数配置等信息，构建出一个类似于UModel的知识图谱。数据会经过预处理，产生一些可以静态分析的指标（部分复用原有成熟度内容），一些更为灵活的指标交由后续的Agent探测。Agent阅读知识图谱，主动尝试注入测试或故障，分析架构问题以及代码设计问题（故障注入复用chaosblade、测试注入采用Agent框架）
2. Agent在给出问题后，会衡量修改影响范围（通过之前获取到的依赖关系评估），并开多个子Agent并行解决问题，互相依赖的Agent将会在同一个工作树下工作，否则将独立进行工作，合并后会进行二次复审

**工作目标：**

调研并复现当前的成熟度评估baseline（初步商用方案1-2个，学术方案1-2个，总计3-4个，学术方案需要至少1个CCF-A会，均需CCF-B类会议以上），需要包含仅源代码作为输入进行成熟度评估方案（类似代码异味分析等）、仅实际部署情况作为输入进行成熟度评估方案（如alibaba intelligent advisor等）
