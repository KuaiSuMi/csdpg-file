# 历史学术实验：Filibuster 复现步骤

Filibuster 属于此前的学术实验，不占当前三项学术或两项商用基线名额。保留实际运行步骤，结果不合并为统一成熟度分数。当前基线见[总调研文档](成熟度评估baseline调研结果.md)。

## 1. 准备源码

需要 Windows PowerShell、Python 3、Git 和 Docker Desktop Linux engine。仅在源码目录尚不存在的新机器执行以下命令；已有源码不要覆盖个人修改。旧版 Python 依赖在容器内安装。

```powershell
New-Item -ItemType Directory -Force baselines/sources | Out-Null
git clone https://github.com/filibuster-testing/filibuster.git baselines/sources/filibuster
git -C baselines/sources/filibuster checkout fa0dd3a1b83ba5aa0f761d50b8c679fa80b2c604
git clone https://github.com/filibuster-testing/filibuster-corpus.git baselines/sources/filibuster-corpus
git -C baselines/sources/filibuster-corpus checkout 1e2e2fc490d928807d56688e1b6c9f5f504c4b24
```

## 2. 运行 Filibuster

先确认 Docker 已启动并使用 Linux engine：

```powershell
docker info --format '{{.OSType}}'
# 预期 linux
python scripts/run_filibuster.py
if ($LASTEXITCODE -ne 0) { throw 'Filibuster experiment failed; inspect results/filibuster' }
```

入口会检查并应用 `filibuster-startup.patch`、用固定 Python 镜像和依赖构建本地运行镜像，然后运行：

1. 四个作者原始 Flask 服务的健康检查与正常业务请求。
2. 作者功能测试，动态约简开/关各一组。
3. 人工收紧为“只接受 200”的对照。
4. 失败反例重放。

服务和故障控制器只在容器内部通信，没有向宿主发布端口。源码挂载为只读，结果目录可写；完成后临时容器自动删除。没有改作者业务逻辑或原功能断言；额外对照脚本写在该次结果目录中。

预期两组各 11 次执行、退出码 0；`strict-control` 和 `strict-replay` **应为退出码 1**，外层脚本将其作为预期结果检查。外层自身应退出 0。如果所有子命令都改成“非零即失败”，会错误地把这两个对照当作实验未完成。

查看 `dynamic.log`、`no-dynamic.log`、`strict-control.log`、`strict-replay.log`、`counterexample.json`、`environment.txt`。只看容器退出码，无法判断是否真的注入过故障。

已知环境适配：作者生命周期检查的调试日志直接拼接 tuple，首次健康检查未就绪时会抛 TypeError；补丁仅加入 `str(service)`。旧 Flask/OpenTelemetry 的兼容依赖已固定在 `baselines/filibuster/requirements.txt`，本轮未重写插桩。
