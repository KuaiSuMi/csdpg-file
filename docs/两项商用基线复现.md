# AppCAT 与 NeuVector 商用基线复现

更新：2026-11-13。完整输入输出及后续 CIS/CVE 证据见[总报告](成熟度评估baseline调研结果.md)与[输入输出清单](基线输入输出清单.md)。

商用对照仅保留 **Microsoft AppCAT for Java** 和 **SUSE Security／NeuVector 开源发行版**。前者分析 Java 源码的云就绪度，后者读取真实 Kubernetes 容器的运行身份。两项均完成受控样例的修改前后实验；不是生产系统验收，也不构成完整成熟度评估。

## 1 选型与版本

| 项目 | AppCAT | NeuVector |
| --- | --- | --- |
| 权威来源 | 微软正式工具，7.x 已 GA | SUSE 正式产品体系及公开开源实现 |
| 实验版本 | Windows amd64 CLI 7.7.0.11 | Controller、Enforcer、Manager 5.6.4 |
| 部署 | Windows 本地 CLI，无需 Azure 资源 | Docker Desktop Linux engine 内的 kind，Kubernetes 1.32.2 |
| 开放程度 | 免费、基于开源组件；以发行包 LICENSE／NOTICE 为准 | NeuVector 开源发行版；未购买或验证付费订阅能力 |
| 直接费用 | CLI 使用费 0 | 开源发行版使用费 0 |
| 输入 | Maven Java 17 小型工程 | 实际 Deployment、Pod、容器运行信息 |
| 复现对象 | 原生 `local-storage-00001` 规则 | 原生 `run_as_root` 风险字段 |

AppCAT 补充 Java 源码的工业云就绪度规则；NeuVector 补充部署运行风险。它们与 Infer/Pulse 的程序错误、feTruth 的方法职责建议分别报告，不能把不同结果相加。软件使用费不包含机器、人工或后续商业支持。

## 2 AppCAT 实验

### 输入与修改

使用[修改前源码](../baselines/fixtures/appcat/before/src/main/java/com/example/CloudAudit.java)和[修改后源码](../baselines/fixtures/appcat/after/src/main/java/com/example/CloudAudit.java)，不是团队真实业务源码。工程无第三方业务依赖，Maven 描述声明 Java 17。

修改前，创建订单后使用 `FileWriter` 将审计内容写入当前工作目录的 `orders.log`；修改后将同一条审计内容写到标准输出。该修改对应原生规则对容器本地日志存储的建议。订单标识、非法数量拒绝行为和审计文本保持一致；没有把业务持久化数据改成临时内存数据。

### 实际结果

| 检查 | 修改前 | 修改后 |
| --- | --- | --- |
| 原生报告 `metadata.status` | Complete | Complete |
| 本地存储规则 `local-storage-00001` 命中 | 1 | 0 |
| 默认编码规则 `utf-8-by-default-00000` 命中 | 1 | 0 |
| 原生 `totalIssues` | 6 | 4 |
| 原生 `totalIncidents` | 7 | 5 |
| `type=violation` 的实例数 | 5 | 3 |

`totalIssues` 和 `totalIncidents` 包含技术发现信息，不能直接当作缺陷数。剩余规则包括缺少 Dockerfile、Java 版本升级提示；本轮没有把全部问题清零。默认编码提示随 `FileWriter` 的移除一起消失，不计为另一项独立修复。

### 重跑

在仓库根目录打开 PowerShell。已有本机环境可直接执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/reproduce_appcat.ps1
```

脚本使用本地 JDK 17 和 AppCAT，依次运行两个阶段，再调用 [verify_appcat.py](../scripts/verify_appcat.py)。验收包括原生报告完整、目标规则命中消失、Java 编译成功及业务契约保持。输出写入新的时间戳目录。

新机器先准备 Python、JDK 17，并从[微软快速开始](https://learn.microsoft.com/en-us/azure/migrate/appcat/appcat-7-quickstart?view=migrate)或清单中的固定下载地址取得发行包。7.7.0.11 Windows amd64 ZIP 的官方 SHA256 为：

```text
191f7ce9f1fefd77585fe4865dc6d21f0ee7819df8842e7d8714b65c6bfef017
```

解压后可通过 `-AppcatHome`、`-Jdk` 指定实际路径。扫描参数固定为 `--target azure-aks --mode source-only --disable-telemetry --output-format json`，保留默认规则集。完整依赖分析、Azure 部署和 Python 源码不属于本轮实验。

## 3 NeuVector 实验

### 实际部署与修改

通过官方 Helm Chart 部署一个 Controller、一个 Enforcer 和一个 Manager。Chart 提交为 `c2dd1543957c1d6ba244da36a6d06f7ab90e50ab`，Chart 版本 2.8.13；其中 `appVersion` 字段仍为 5.5.1，**实际镜像明确固定为 5.6.4**。平台部署在 `maturity-neuvector` 命名空间，API 只经本机回环端口转发访问。

在独立实验命名空间部署 Node HTTP 服务，镜像和业务代码不变，仅将容器 `securityContext.runAsUser` 从 0 调整为 1000。运行后读取真实 Pod 的 `containerID`，用该 ID 查询 NeuVector `/v1/workload/{id}`；同时在该 Pod 中读取真实进程 UID 并请求 HTTP 服务。没有使用自定义风险规则或以 Kubernetes 字段自行计算替代平台结果。

两阶段均使用同一容器镜像，实际镜像 ID：


### 本机重跑

保持 Docker Desktop Linux engine 和本地 kind 集群运行。平台已安装，管理员密码保存在被 Git 忽略的 `.runtime/neuvector/admin-password.txt`。

在单独终端开启 API 端口转发；若本轮的转发仍运行，无需重复启动：

```powershell
kubectl --kubeconfig .runtime/tools/maturity-kubeconfig -n maturity-neuvector port-forward --address=127.0.0.1 service/neuvector-svc-controller-api 10443:10443
```

然后执行：

```powershell
.runtime/commercial-venv/Scripts/python.exe scripts/reproduce_neuvector.py --kubeconfig .runtime/tools/maturity-kubeconfig --password-file .runtime/neuvector/admin-password.txt --output "results/commercial/neuvector/$(Get-Date -Format yyyyMMdd-HHmmss)"
```

脚本创建独立命名空间，部署两个阶段并比较原生结果、实际 UID、HTTP 响应和镜像 ID，最后删除实验命名空间并退出 API 会话。它仅对回环端口转发使用实验环境自签名 TLS，不应改成连接外部地址并跳过证书校验。

### 新环境安装

准备 Docker Linux engine、kind、kubectl、Helm、Python。以下按本项目路径放置 kind 0.27.0 与 Helm 3.19.0；`kubectl` 和 `python` 应在 PATH 中。仅在同名集群、目录尚不存在的新机器执行创建／克隆命令；已有环境直接使用前面的本机重跑步骤。

创建隔离的单节点 kind 集群，导出 kubeconfig，并安装 Python 依赖：

```powershell
New-Item -ItemType Directory -Force .runtime/tools, .runtime/neuvector, baselines/sources | Out-Null
.runtime/tools/kind.exe create cluster --name maturity-baselines --image kindest/node:v1.32.2 --kubeconfig .runtime/tools/maturity-kubeconfig

.runtime/commercial-venv/Scripts/python.exe -m pip install -r baselines/commercial-requirements.txt
git clone https://github.com/neuvector/neuvector-helm.git baselines/sources/neuvector-helm
git -C baselines/sources/neuvector-helm checkout c2dd1543957c1d6ba244da36a6d06f7ab90e50ab
```

拉取三份 5.6.4 镜像和固定实验镜像后，导入 kind。Docker Desktop 29 的多平台镜像导出在本轮曾导致 kind 导入报缺失 digest，采用显式单平台归档解决：

```powershell
docker pull --platform linux/amd64 neuvector/controller:5.6.4
docker pull --platform linux/amd64 neuvector/enforcer:5.6.4
docker pull --platform linux/amd64 neuvector/manager:5.6.4
docker pull --platform linux/amd64 node@sha256:0a7108bf6c7bf5de370ffb1a3ed6be93d405b43ff159f681a8d18c0e2bc2e402
docker tag node@sha256:0a7108bf6c7bf5de370ffb1a3ed6be93d405b43ff159f681a8d18c0e2bc2e402 node:22-alpine
docker image save --platform linux/amd64 -o .runtime/neuvector/images-amd64.tar neuvector/controller:5.6.4 neuvector/enforcer:5.6.4 neuvector/manager:5.6.4 node:22-alpine
.runtime/tools/kind.exe load image-archive .runtime/neuvector/images-amd64.tar --name maturity-baselines
```

使用[部署配置](../baselines/neuvector/values.yaml)。生成随机 `bootstrapPassword` 写入被忽略的本地文件，然后安装；JSON 也是合法的 YAML 输入：

```powershell
$nvBootstrap = 'Nv!' + [guid]::NewGuid().ToString('N') + 'aA1'
$nvSecretJson = @{ bootstrapPassword = $nvBootstrap } | ConvertTo-Json
[IO.File]::WriteAllText((Join-Path (Get-Location) '.runtime/neuvector/secret-values.yaml'), $nvSecretJson)
.runtime/tools/helm/helm.exe install maturity-neuvector baselines/sources/neuvector-helm/charts/core --namespace maturity-neuvector --create-namespace --kubeconfig .runtime/tools/maturity-kubeconfig -f baselines/neuvector/values.yaml -f .runtime/neuvector/secret-values.yaml --wait --timeout 8m
```

平台首次登录要求更改初始密码。经 API `/v1/auth` 的 `password.new_password` 字段，或在管理页面完成密码更新后，将新密码以 UTF-8 纯文本保存在 `.runtime/neuvector/admin-password.txt`，再按本机重跑步骤执行。管理页面的本地访问命令如下，启动后访问 `https://127.0.0.1:8443`：

```powershell
kubectl --kubeconfig .runtime/tools/maturity-kubeconfig -n maturity-neuvector port-forward --address=127.0.0.1 service/neuvector-service-webui 8443:8443
```

不再需要实验平台时，执行 `.runtime/tools/helm/helm.exe uninstall maturity-neuvector -n maturity-neuvector --kubeconfig .runtime/tools/maturity-kubeconfig`，再检查该实验命名空间。不要删除原有的其他实验资源。

## 4 结果接入图谱

两个读取器已接入 `BaselineCollector`，由项目原有的 `BuildPipeline` 生成图谱 JSON。以下操作读取已保存的实验结果。

| 入口 | 输入目录中的文件 | 处理内容 |
| --- | --- | --- |
| `--appcat` | `report.json` | 核对报告完成状态与实例数量，按工程、文件、目标平台和规则归组，保留严重程度、源码位置、建议及原始记录 |
| `--neuvector` | `workload.json`、`pods.json`、`deployment.json`；有 `score-metrics.json` 时一并读取 | 核对 Pod UID、容器 ID、命名空间和 Deployment 选择器，导入 `run_as_root`、`privileged`；全局分数单独保存 |

AppCAT 的规则命中记为候选，技术发现和扫描统计记为观测值。同一文件的一条规则可以包含多处命中，行号变化仍归到原检查项。

NeuVector 每份工作负载响应对应一个实测容器。对照使用 Deployment 与容器名，Pod UID 和容器 ID 随每次运行保存；风险字段 `true` 对应该项检查失败，`false` 对应通过。全局风险分数挂在集群对象上。

### 4.2 合并到已有项目图谱

添加 `--base-graph` 和 `--bindings`。映射左侧是工具对象键，右侧填写已有图谱的节点 ID：

```json
{
  "appcat:.:src/main/java/com/example/CloudAudit.java": "已有源码节点ID",
  "k8s:<集群名>/<命名空间>/Deployment/<部署名>": "已有部署节点ID"
}
```

AppCAT 对象键的格式是 `appcat:<project.path>:<location>`；工程级问题的 location 使用 `<project>`。NeuVector 的集群名来自 `--cluster`，其余身份来自导出的 Kubernetes 快照。Deployment 节点的名称、`cluster` 和 `namespace` 属性应与输入一致。

将占位内容替换后执行：

```text
python scripts/build_baseline_graph.py --appcat <AppCAT阶段目录> --neuvector <NeuVector阶段目录> --cluster <集群名> --namespace <原图谱项目标识> --base-graph <已有图谱JSON> --bindings <对象映射JSON> --output <合并后图谱JSON>
```

已有节点的属性会保留，新增检查结果通过 `OBSERVED_BY` 关系连接，原始报告片段保存在 `provenance` 中。
