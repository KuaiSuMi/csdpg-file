## 2. feTruth：先重放论文，再运行本项目源码

### 2.1 准备工具源码、JDK 和模型文件

本机已经准备好这些内容，可以从 2.3 开始。新机器需要 JDK 17 和 Docker Desktop 的 Linux engine。

feTruth 项目包装脚本目前使用固定路径 .runtime/jdk17/jdk-17.0.20.1+1/bin/java.exe。将对应 [Temurin 17 发布包](https://github.com/adoptium/temurin17-binaries/releases/tag/jdk-17.0.20.1%2B1)解压到该位置。

~~~powershell
git clone https://github.com/lyoubo/feTruth.git baselines/sources/feTruth
git -C baselines/sources/feTruth checkout b4f8d5c4fbf655e5615246f2849ccc3825db8e7d
& $Python scripts/download_fetruth_weights.py
if ($LASTEXITCODE -ne 0) { throw '词向量下载或校验失败' }
Copy-Item baselines/sources/feTruth/word2vec/new_model.bin .runtime/fetruth/word2vec/new_model.bin
~~~

下载器从作者指定的 Zenodo 材料取得两个大数组，检查分段响应和包的校验值。new_model.bin 是仓库里的索引文件，需要一起放入目录；不能只下载两个 .npy 就开始运行。

准备后，.runtime/fetruth/word2vec 中应有三个文件：

~~~text
new_model.bin
new_model.bin.trainables.syn1neg.npy
new_model.bin.wv.vectors.npy
~~~

两个数组各约 485 MB，需预留下载包、解压文件和容器空间。项目脚本通过硬链接复用数组，要求 .runtime 下这些目录在同一磁盘卷。

### 2.2 安装作者要求的旧版 Python 依赖

作者使用 Python 3.6、TensorFlow 2.4.0、Keras 2.4.3、NumPy 1.19.5 等旧版本。这里用容器隔离，实际依赖在 baselines/fetruth-requirements.lock。

先准备 Linux Python 3.6 的 wheel：

~~~powershell
New-Item -ItemType Directory -Force .runtime/wheels | Out-Null
& $Python -m pip wheel --no-deps --wheel-dir .runtime/wheels termcolor==1.1.0
if ($LASTEXITCODE -ne 0) { throw 'termcolor wheel 构建失败' }
$env:WRAPT_INSTALL_EXTENSIONS = 'false'
& $Python -m pip wheel --no-deps --wheel-dir .runtime/wheels wrapt==1.12.1
if ($LASTEXITCODE -ne 0) { throw 'wrapt wheel 构建失败' }
Remove-Item Env:WRAPT_INSTALL_EXTENSIONS
& $Python -m pip download --find-links .runtime/wheels --dest .runtime/wheels --only-binary=:all: --platform manylinux2010_x86_64 --platform manylinux1_x86_64 --python-version 36 --implementation cp --abi cp36m -r baselines/fetruth-requirements.lock
if ($LASTEXITCODE -ne 0) { throw '旧版依赖下载失败' }
~~~

这些平台参数控制下载目标，不会把宿主机 Python 降级。下载成功后创建实验容器：

~~~powershell
docker pull python@sha256:e10aa83604948c6d8d9f72a9a20193d84bb2dbe550b725eb5208387117fde065
if ($LASTEXITCODE -ne 0) { throw 'Python 容器镜像下载失败' }
$TaskRoot = (Get-Location).Path
docker run -d --name maturity-fetruth --memory 4g --mount "type=bind,source=$TaskRoot,target=/workspace" python@sha256:e10aa83604948c6d8d9f72a9a20193d84bb2dbe550b725eb5208387117fde065 sleep infinity
if ($LASTEXITCODE -ne 0) { throw 'feTruth 容器创建失败' }
docker exec maturity-fetruth python -m pip install --no-index --find-links /workspace/.runtime/wheels -r /workspace/baselines/fetruth-requirements.lock
if ($LASTEXITCODE -ne 0) { throw '容器依赖安装失败' }
~~~

本段仅用于首次创建。已有名为 maturity-fetruth 的容器时不要再次 docker run；先确认它绑定的是当前交付目录，再使用 docker start maturity-fetruth。若移动了宿主机目录，旧容器的 /workspace 不会自动跟着变。

### 2.4 运行当前项目的 Java 示例

~~~powershell
& $Python scripts/run_fetruth_project.py --source baselines/sources/maturity-evaluate/examples/comprehensive_test_repo/java_app
~~~

成功时会打印新的 results/fetruth-project/时间戳 目录，以及候选数。本次保存的结果为 1 个候选方法、2 个候选组合、1 条建议。

| 文件 | 读它可以知道什么 |
| --- | --- |
| extraction.log | Java 解析和特征提取是否成功 |
| features.json | 源方法、目标类候选和结构特征 |
| inference.log | 原模型是否正常加载和运行 |
| recommendations.tsv | 最终输出的源方法和目标类 |
| summary.json | 输入和工具提交、模型摘要、覆盖数、阈值 |

要分析其他 Java 项目，把源码放到当前交付目录下的 Git 工作区中，再更换 --source。当前脚本要求输入位于交付目录内、存在 Java 文件、能够取得 Git 提交号。它不会扫描 Python，也不会自动执行方法移动。

较新源码流程与论文归档模型存在已记录差异。两组结果分别报告；新项目得到 0 条或更多建议时，先查看提取覆盖、输入版本和模型，不能据此认定代码更成熟或复现失败。
