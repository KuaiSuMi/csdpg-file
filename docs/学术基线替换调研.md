# 学术基线替换调研

历史调研：本文保留 GLITCH/Infer 的旧选择过程。当前学术基线固定为 **Infer/Pulse + feTruth**，见[最新复审结论](学术基线复审结论.md)。

更新：2026-11-13。

本轮以 **GLITCH 与 Infer/Pulse** 替换 Kivi、Reynard 的通用学术基线位置。两项均有 CCF-A 主会研究论文依据，不依靠 feTruth 凑足“至少一个 A”。feTruth 保留为 Java Feature Envy 专项对照，旧 Kivi、Reynard 实验保留为历史验证材料。

## 准入条件

“简单配置”指安装一次后，换项目只提供路径、受支持的语言/项目类型，以及必要的构建命令或依赖。不能要求每个项目重新编写业务请求、正确性断言、故障策略或形式化模型。

“通用”指同一种受支持技术下能复用同一套分析器与内置规则，不能理解为支持所有语言和所有部署平台。用不同开源项目的原样源码验证迁移使用，用受控样例验证修改后的报告变化；二者的作用不同。

| 候选 | 学术依据 | 换项目需要做什么 | 结论 |
| --- | --- | --- | --- |
| GLITCH | ASE 2022 Research Papers，CCF-A | 指定 IaC 目录、Ansible/Chef/Puppet 及文件/模块类型；使用内置 security 检查 | 入选，覆盖 IaC 静态安全异味 |
| Infer/Pulse | CAV 2020 研究论文，CCF-A；OOPSLA 2022 后续方法研究，CCF-A | 提供源码及能成功执行的构建命令；启用内置 Pulse 分析器 | 入选，覆盖源码空指针、内存与资源错误 |
| Kivi | USENIX ATC 2024，CCF-A | 整理集群模型、支持的对象与待验证性质 | 不符合本轮低定制要求，退出通用选型 |
| Reynard | ICSE 2026 Research Track，CCF-A | 接入代理、业务请求和业务正确性断言 | 不符合无需业务规则要求，退出通用选型 |
| Filibuster | SoCC 2021，CCF-B | 接入故障注入与服务级测试，正确行为仍需使用方定义 | 与 Reynard 有同类定制成本，不作替代 |
| feTruth | FSE 2023 Research Papers，CCF-A | Java 源码与模型环境，不需业务规则；公开模型/工作流存在已记录差异 | 保留专项结果，本轮不计入两项通用基线 |
| Arcan | 当前归档为 ICSA Workshops 2017 | 架构异味分析，但现有论文属于 Workshop | 本次证据不能满足 B 及以上主会研究论文要求 |

不根据 stars 判定学术级别，也不把“支持自定义规则”误判为“必须编写规则”。本轮两项的扫描命令均未加载项目自定义规则。

## 正式发表与实现关系

**GLITCH**：Nuno Saavedra、João F. Ferreira，*GLITCH: Automated Polyglot Security Smell Detection in Infrastructure as Code*，ASE 2022，12 页，DOI [10.1145/3551349.3556945](https://doi.org/10.1145/3551349.3556945)。[主会研究论文页](https://conf.researchr.org/details/ase-2022/ase-2022-research-papers/74/GLITCH-Automated-Polyglot-Security-Smell-Detection-in-Infrastructure-as-Code)、[作者代码](https://github.com/sr-lab/GLITCH)、[论文全文](../references/papers/glitch-ase2022.pdf)。本次使用作者 v1.0.1 标签，保留原生 security 检查与默认配置。2023 年同名工具的扩展介绍属于 Tool Demonstrations，本轮不靠那篇短文满足等级要求。

**Infer/Pulse**：Azalea Raad 等，*Local Reasoning About the Presence of Bugs: Incorrectness Separation Logic*，CAV 2020，225–252 页，DOI [10.1007/978-3-030-53291-8_14](https://link.springer.com/chapter/10.1007/978-3-030-53291-8_14)。[论文全文](../references/papers/pulse-cav2020.pdf)第 5 节明确说明在 Infer 的 Pulse 中实现该分析。当前 [Infer 1.3.0 的 Pulse 文档](https://fbinfer.com/docs/checker-pulse/)给出不需注解的 Java 用法；本次固定这个公开发行版运行 `--pulse-only`。

相关后续论文 *Finding Real Bugs in Big Programs with Incorrectness Logic*，OOPSLA 2022，DOI [10.1145/3527325](https://doi.org/10.1145/3527325)，在[会议研究论文页](https://2022.splashcon.org/details/splash-2022-oopsla/16/Finding-real-bugs-in-big-programs-with-incorrectness-logic)可核对。它评测的科学原型叫 **Pulse-X**；论文说明其 manifest 判定的一个放宽版本用于同系分析器 Pulse。**Infer/Pulse 1.3.0 不是 Pulse-X 论文归档程序**，因此不把这次输出标为 Pulse-X 的原始实验复现，也不沿用论文中的准确率、漏洞数或耗时。

本轮完成的是固定公开版本的功能复现与跨项目可用性验证，不是复跑 GLITCH 的 196,755 份脚本或 Pulse-X 的完整 OpenSSL/大型项目实验表。

CCF 等级依据 [软件工程/系统软件/程序设计语言目录](https://www.ccf.org.cn/Academic_Evaluation/TCSE_SS_PDL/)与[计算机科学理论目录](https://www.ccf.org.cn/Academic_Evaluation/TCS/)，并复核[本地第七版目录](../references/ccf-seventh.pdf)第 27 页（ASE、OOPSLA）和第 41 页（CAV）。本轮官网直接打开返回 405，搜索索引可读；本地镜像来源已记录在 references，不将镜像作为分类制定者。

## 输入、机制与输出

| 项目 | GLITCH | Infer/Pulse |
| --- | --- | --- |
| 输入 | IaC 文件/目录，技术类型，文件类型或 role/module 结构 | 能编译的源码、依赖和构建命令 |
| 核心步骤 | 各语言解析器转换为统一中间表示，再运行内置 SecurityVisitor | 捕获编译，生成程序中间表示；跟踪指针/值、控制流和函数调用，自动推导局部状态与调用摘要 |
| 判断依据 | HTTP 未使用 TLS、硬编码凭据等已有安全异味模式 | 内置空指针、释放后使用等程序错误语义；不需要编写业务断言 |
| 输出 | 文件、行号、规则编号、代码片段，分类统计、文件数与行数 | report.json、report.txt、文件/行号、错误种类、解释与 bug_trace；附捕获和分析日志 |
| 项目间变化 | 路径、技术类型和模块标志 | 路径、标准构建命令、依赖环境 |
| 本轮固定不变 | security 检查集合、作者默认词表 | Pulse 分析器及默认检查配置 |

GLITCH 的规则由工具作者预先实现。用户可以扩展，但这不是本轮使用条件。默认词表也会产生需要复核的提示，例如合法 root 账户、代码注释，不能将每条异味直接叫作确认漏洞。

Pulse 中的“断言/逻辑状态”是程序分析内部推导出来的事实，例如某变量此处为空。它不要求用户像 Reynard 那样写“支付失败时订单必须回滚”的业务断言。仅在特定参数下成立的问题可能保留为 latent，调用处满足条件时才报告。有限路径探索、未知库函数模型等仍会带来漏报或误报；零报告不等于程序正确。

## 对本项目的适用范围

GLITCH 为 IaC 配置提供文件级证据，Infer/Pulse 为源码提供函数及调用路径证据，都可作为项目诊断结果的外部对照，并比较修改前后的原生输出。两项不会自动生成 SESORA 六维成熟度总分。

GLITCH v1.0.1 不支持直接扫描 Kubernetes Deployment YAML 或 Terraform，不能把文件后缀是 YAML 当作支持 Ansible。Infer/Pulse 的本轮实测范围为 Java，不覆盖 Python/FaaS。Kubernetes 的已有安全扫描继续由 NeuVector 提供；团队 otel-demo、Python 主体和业务容错验证仍未覆盖。新选择降低的是逐项目业务定制成本，不代表保留了 Kivi 的调度性质证明或 Reynard 的业务故障测试能力。

固定版本、重跑命令与本轮原始结果见[两项学术基线复现](两项学术基线复现.md)。
